# Findings

Observations that aren't rules, decisions or issues yet. How to log: [logging.md](logging.md).

- 2026-10-23: Sharing finished proofs across parallel agents cut token use 17% and let some agents succeed where they failed alone. EMD equivalent: a shared per-repo cache of working build commands, flaky-simulator fixes and reliable UI selectors. Different domain, so don't expect the same number. [source](https://www.anthropic.com/research/formal-verification) → next: issue after v1
- 2026-10-23: On a host with little free RAM (heavy swapping), a Play Store emulator image (2 GB guest) hits ANR dialogs ("System UI", "Digital Wellbeing isn't responding") that cover the app, and an Expo debug app cold-starts in ~35s, past Maestro's default wait. Fix that worked: `adb shell settings put global hide_error_dialogs 1`, headless `-no-window -cores 2`, and `extendedWaitUntil` (90s) after `launchApp`. Measured in the smoke test on 2026-10-23. → next: M1 build/run issue and queue design
- 2026-10-23: `avdmanager` has no `--sdk_root` flag and finds the SDK from its own location, so a Homebrew-installed copy fails with "Package path is not valid". Install `cmdline-tools;latest` into the SDK root and use that copy. Observed in the smoke test on 2026-10-23. → next: setup/`doctor` issue
- 2026-10-24: Expo SDK 58 / React Native 0.88 packages declare `swift-tools-version: 6.2`, so they need Xcode 26 or newer; Xcode 16.2 fails with "package 'apple' is using Swift tools version 6.2.0 but the installed version is 6.0.0". On macOS 14 the newest Xcode is 16.2 and `brew install xcodes` is refused (needs Sequoia or later). Observed in the iOS smoke test. → next: setup/`doctor` issue
- 2026-10-24: Maestro on iOS failed with "iOS driver not ready in time" and "Device became unreachable" while the host was overloaded (load above 40 after a macOS update, little free RAM); it passed once load fell to ~6. Set `MAESTRO_DRIVER_STARTUP_TIMEOUT=300000`. One full flow also failed at the "Tapped" assertion under load, then passed on rerun. Observed in the iOS smoke test. → next: M1 step runner issue
- 2026-10-23: Setup design: detect the stack from project files (`ios/` or `.xcodeproj`, `build.gradle`, `expo` in package.json or `app.json`), show one plan to confirm, download heavy pieces (simulator runtimes, emulator images) on first use, and ask questions only outside a project, with several apps, or to override; `--platform` flag for CI. (planning decision) → next: setup issue
- 2026-10-25: With two cold Expo iOS builds in parallel the host load average reached ~206 and Expo's post-install `simctl openurl` timed out (POSIX 60), failing the launch after a successful build. Heavy jobs need the M2 queue. → next: M2 queue (decision 0003)
